# Hook library

A hook is three layers that work together without repeating each other:
**visual** (what moves in frame 0–2 s) + **on-screen text** (≤ 6 words) + **VO line** (optional, ≤ 8 words).
In a muted feed the visual and text must carry it alone.

## Rules
1. Frame 0 shows motion and either the promise or the product mid-action.
2. The text is 6th-grade simple, active voice, one possible reading, and names the viewer ("you", a role) or uses contrast or a concrete number.
3. Clear beats clever. A curiosity hook must still make the topic obvious.
4. The hook truthfully previews something the video pays off. Bait = high hook rate, low hold rate.
5. The next beat continues the hook's premise; it never pivots to "Introducing…".
6. Don't name the product in the first card unless the name *is* the news (big brands, version launches).
7. Typing into an empty prompt box is not a hook; a few seconds in, it's a fine story step.
8. Numbers are in the viewer's units (₹, orders, payouts, days, clicks), never UI mechanics
   ("57 pages" of a paginated table confused a founder).
9. The line after the hook **promises** the payoff with a number ("In 3 clicks."). Don't turn
   it into a puzzle ("Count the clicks"); the viewer stays to see the promise kept.

## Four ways a hook fails (check each)
- **Delay:** the point arrives after 2 s.
- **Confusion:** two readings, jargon, or too many words.
- **Irrelevance:** the target viewer doesn't see themselves.
- **Disinterest:** no contrast, number, tension, or stakes.

## Patterns (generic SaaS examples, swap in real ledger facts)

| # | Pattern | How it works | Example (text) | Visual idea |
|---|---|---|---|---|
| 1 | Role callout | Name who it's for + their pain | "PMs: stop writing release notes" | release notes writing themselves |
| 2 | Old vs new | Contrast in one line | "Weekly report: 3 hours → 1 click" | split screen collapsing to one |
| 3 | Number + time | Concrete, measurable speed | "Signup to invoice in 90 seconds" | timer running beside the flow |
| 4 | Result first | Show the finished output, then rewind | "12 seconds." | finished dashboard, camera pulls back |
| 5 | Villain | Name the enemy (a habit/tool type, never a brand) | "Spreadsheets are where deals die" | a sheet cracking into rows |
| 6 | Contrarian | Flip common advice | "You don't need another dashboard" | dashboards stacking, then one view |
| 7 | Relatable moment | A time-stamped scene they've lived | "11pm. Still merging CSVs." | clock + CSV windows multiplying |
| 8 | The question with input | Question with the real input in it | "What if your changelog wrote itself?" | the blank filled by real commit text |
| 9 | Bold claim (ledger-true) | Surprising but provable | "This inbox answers 80% of tickets" | tickets resolving in a stream |
| 10 | Self-check | A yes/no the viewer answers | "Still copying data between tools?" | cursor ping-ponging between apps |
| 11 | Before/after split | Same task, two outcomes | "Same task." | 14 tabs vs 1 view |
| 12 | Timer | Countdown/stopwatch frames the demo | "0:07" | stopwatch stops as task completes |
| 13 | Missing piece | Tease the one thing | "The setting that halved our queue" | toggle flips, queue graph drops |
| 14 | Money | Dollars beat hours | "Recovered $40k in failed payments" | counter climbing in the accent |
| 15 | Casual reaction | Human, informal voice | "Okay, this filter is unfair" | filter applied, results snap |
| 16 | Social proof | Others are already doing it | "2,000 teams switched this week" | live counter ticking |
| 17 | Feature does the hook | The feature transforms something recognisable in 0.5 s | (no text, or one word) | the feature acting on a familiar image |
| 18 | Stack | 3 one-second micro-hooks (role → pain → number) | "Founders." / "Manual invoicing?" / "Done in 1 click" | three fast cuts on the beat |
| 19 | Time-stamped stake | Clock time + who needs what + the number, built as two lines | "11:48 PM." / "Your accountant needs 1,126 payouts." | the real page with the number visible; the request arrives as a WhatsApp |
| 20 | Promise with a count | The beat after the hook: the answer, quantified | "Here's the file. In 3 clicks." | cursor heads for the button; a counter appears at 0 |

## Hook battery (step 4 of the process)
1. Write ≥ 5 hooks from **different patterns** and **different motivations** (save time, make money, avoid embarrassment, look good to the boss, curiosity, belonging). Don't reword one hook five ways.
2. Score each 1–5 on: clarity in 1 s, relevance to the target viewer, contrast/stakes, truth (ledger-backed), buildability (can we show it with real UI?).
3. Pick the top one; keep two runners-up as **A/B variants**: same body, only the first ≤ 3 s swaps. Note them in SCRIPT.md so motion-director can render variants cheaply.
4. Paid ads: test hooks by hook rate (3-second views ÷ impressions; ~20–30 % is good) and hold rate. Strong hook + weak hold = the body doesn't continue the hook's promise.
